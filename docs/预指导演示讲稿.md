# 岔路口预指导演示讲稿（目标约 2 分 40 秒）

## 00:00–00:15｜痛点

画面：已导入官方 Excel 的应用首页。

“大三准备国考时，最难受的不是没有职位，而是翻完几万行职位表，也不知道自己真正能报几个，更不敢直接相信 AI 随口给的数字。”

## 00:15–00:45｜画像出结果

画面：依次指向文件、画像和三态数字。

“这是岔路口。我导入国家公务员局发布的二零二七国考招考简章，程序读取四个数据表、一万九千四百二十六条职位。输入法学、本科、学士、群众、两年基层经历和北京东城区，立即得到符合一个、待确认十二个、不符一万九千四百一十三个。每个数字都是程序算的，不是 AI 编的。”

## 00:45–01:10｜点击原表溯源

操作：点“符合”卡片，再点民盟中央职位，展示 sheet、第 58 行和 27 列。

“点符合数，看到这条民盟中央职位。再点进去，可以看到它来自中央党群机关第五十八行，以及原表二十七列。每项条件都单独核对；不符会标红，不确定标黄，不会把待确认说成能报。”

## 01:10–01:35｜地点差分

操作：关闭详情。取消东城区，选择西城区；再把东城区加回来，展示 +1 和新增职位。

“现在只改工作地点。先取消东城区，再选西城区，符合数发生变化；然后把东城区加回来，符合数从零变一，页面醒目显示加一，并列出新增的就是这条第五十八行职位。变化只归因于地点，其他画像没有改变。”

## 01:35–02:15｜真实 Bug 与 Prompt 链

画面：展示本次 Kimi 对话中“第 58 行预期符合、实际不符”及“及以上截取长度”根因的截图；随后可切到 GitHub 的 `prompt-log/P-004.md`。

“开发也不是一次写对。测试第五十八行时，我发现预期符合却显示不符。我没有让 AI 盲目重写，而是要求按复现、根因、证据、修改、验证来排错。逐项输出发现只有学历被误判，根因是代码把‘及以上’三个字误按四个字符截取，导致本科及以上反而把本科排除。我引导 AI 只改截取长度，再跑同一组真实职位，结果从红变绿。这份 Prompt 链和每次代码提交都公开在 GitHub。”
